# Dashgen

Сборка дашбордов Qlik Sense (on-premise) из Excel с помощью ИИ: по Excel-файлу и короткому описанию отчёта приложение создаёт приложение Qlik с моделью данных, мастер-элементами и листами.

**Принципы**

1. ИИ решает, код исполняет — модель возвращает только spec.json по строгой схеме.
2. Данные остаются внутри контура — в ИИ уходит только безопасный профиль без значений.
3. Человек утверждает — макет → черновик → утверждение → публикация.
4. Источники подключаются адаптерами — Excel, CSV, базы данных, QVD.
5. Воспроизводимость — одна команда, журнал действий, код без сертификатов и ключей.

**Документация**

- `Dashgen сборка дашбордов Qlik Sense из Excel с ИИ.docx` / `.md` / `.pdf` — проектная документация v1.0 (архитектура, приватность, этапы 0–9, риски).
- `Dashgen — Дополнение 1 (источники, дизайн-система, цикл утверждения).docx` — адаптеры источников (CSV, БД, QVD), дизайн-система (тема + архетипы), жизненный цикл (макет → черновик → публикация), этапы 10–13.

**Структура**

```
spec/schema.v1.json   — контракт: JSON-схема spec v1 (блок sources: inline | excel | qvd)
src/
  config.js           — загрузка конфигурации (пути кроссплатформенные: Mac и Windows)
  engine.js           — подключение к Engine API (enigma.js, сертификаты, X-Qlik-User)
  spec-validator.js   — валидация spec по схеме + ссылки на меры/измерения
  sources/            — слой адаптеров: excel.js (профиль), qvd.js (заголовок XML); SourceProfile
  privacy.js          — граница контура: безопасный профиль, запрещённые колонки, журнал
  qvs-generator.js    — скрипт загрузки: inline | lib:// Excel | QVD
  builder/            — templates.js (свойства клиента 1.39.8), objects.js, index.js (сборка)
  verify.js           — ошибки объектов, сверка числа строк с источником
cli.js                — команды: check | profile | build [--verify]
prototype/            — проверенный прототип build_dashboard_v2.js и выгрузка шаблона клиента
examples/             — демо-spec, повторяющий тестовый дашборд прототипа
```

**Команды**

```
npm run ui                                           # интерфейс: http://127.0.0.1:4748 (только localhost)
node cli.js check examples/spec-sales-inline.json    # валидация spec
node cli.js profile data.xlsx [--sheet Лист1]        # профиль Excel/QVD + dry run для ИИ
node cli.js build spec.json --verify                 # сборка в Qlik + проверка
```

**Интерфейс** (папка `public/`, сервер `server.js` без внешних зависимостей): экраны конвейера из дизайн-макета — Источник (профиль Excel/QVD), Приватность (dry run), Спецификация (проект ИИ + валидация схемы), Макет (сетка 24×12 из spec), Сборка и проверка (журнал + verify), Публикация (журнал утверждений + QRS-стрим), Подключения (проверка портов 4747/4242). Сервер слушает только 127.0.0.1.

**Публикация** (этап 9): черновик → утверждение (журнал `logs/approvals.jsonl`, привязка к хешу spec) → PUT `qrs/app/{id}/publish` в стрим (QRS 4242). Нюансы зашиты в `src/qrs.js`: метод PUT (POST даёт 404) и обязательный Content-Length (HTTP.sys отвечает 411).

**ИИ-генерация spec** (этап 5): провайдер Z.ai (GLM, OpenAI-совместимый endpoint), температура 0, контур самоисправления — до 3 попыток с возвратом ошибок валидации модели. Ключ: `~/.dashgen/zai_api_key` (chmod 600) или env `ZAI_API_KEY` — в git и чат не вставлять. В модель уходит только безопасный профиль (privacy schema) и текст описания; каждая отправка пишется в `logs/privacy-send.jsonl`.

Настройки окружения — в `config.json` (не коммитится; шаблон: `config.example.json`). Поддержка `~` в путях делает конфиг одинаковым для macOS и Windows.

**Безопасность**

Сертификаты Qlik, ключи API, журналы отправок хранятся локально и исключены из репозитория (`см. .gitignore`). Режимы приватности и dry run описаны в разделе 8 документации.
