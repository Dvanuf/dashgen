# Dashgen: сборка дашбордов Qlik Sense из Excel с ИИ

*Проектная документация, версия 1.0, 3 ноября 2026*

## 1. Назначение документа

Документ описывает проект целиком: цель, среду, пройденный путь, архитектуру, план разработки и каждый файл проекта с примерами. Он написан так, чтобы с проектом мог работать другой разработчик или ИИ-модель без доступа к прежней переписке. Правила работы с проектом собраны в разделе 16, полный код рабочего скрипта в приложении A.

## 2. Цель и контекст

**Цель:** по Excel-файлу и короткому описанию отчёта приложение создаёт в Qlik Sense (on-premise) приложение с моделью данных, мастер-элементами и листами. Готовый файл .qvf выгружается из Hub или QMC (готовый .qvf вне движка Qlik собрать нельзя, это закрытый бинарный формат).

**Среда:**

| Компонент | Значение |
| --- | --- |
| Рабочая машина | Mac, терминал zsh, Node.js v26.13.0, папка проекта \~/qlik\_build |
| Qlik | Sense Enterprise on Windows (on-premise), Qlik Cloud не используется |
| Сервер | dc3-qliks-ap-03.onyx.local, Engine: порт 4747 (проверено командой nc, ответ succeeded) |
| QRS API | порт 4242 (пока не проверялся) |
| Аутентификация | клиентские сертификаты из QMC (имя машины Mac-dev) и заголовок X-Qlik-User |
| Библиотеки Node | enigma.js, ws |
| Схема Engine | enigma.js/schemas/12.612.0.json |
| Версия свойств объектов | 1.39.8 (версия клиента Qlik на сервере) |

**Что работает сейчас.** Одна команда `node build_dashboard_v2.js` создаёт приложение TEST\_Dashboard\_Inline: inline-данные (600 заказов), 3 мастер-измерения, 4 мастер-меры, лист «Обзор» с тремя фильтрами, четырьмя KPI, линейным графиком, столбчатой диаграммой и таблицей. Результат проверен в Hub.

## 3. Принципы

1. **ИИ решает, код исполняет.** Модель возвращает только описание дашборда (spec.json) по строгой схеме. Объекты Qlik, скрипт загрузки и раскладку создаёт проверенный код.
2. **Данные остаются внутри.** Excel читается локально и загружается на внутренний сервер Qlik. В ИИ уходит только безопасный профиль без значений.
3. **Человек утверждает.** Перед отправкой в ИИ и перед сборкой пользователь видит и подтверждает результат.
4. **Источники подключаются адаптерами.** Excel первый, затем CSV, базы данных, QVD.
5. **Воспроизводимость.** Одна команда, журнал действий, код в GitLab без сертификатов и ключей.

## 4. Установка окружения (повторяемая инструкция)

**Шаг 1. Node.js LTS.** Установщик .pkg с nodejs.org (или brew install node). Проверка: `node -v`, `npm -v`.

**Шаг 2. Папка и библиотеки.**

```
mkdir -p ~/qlik_build && cd ~/qlik_build
npm install enigma.js ws
```

**Шаг 3. Сертификаты.** В QMC: Certificates, указать Machine name (например, Mac-dev), включить Include secret key, нажать Export certificates. Получить архив с файлами root.pem, client.pem, client\_key.pem (server.pem и server\_key.pem не нужны). Распаковать:

```
mkdir -p ~/qlik_build/certs
unzip -j ~/Downloads/Mac-dev.zip -d ~/qlik_build/certs
chmod 600 ~/qlik_build/certs/client_key.pem
```

Файлы ключей нельзя пересылать, коммитить в git и вставлять в чат.

**Шаг 4. Проверка сети.**

```
nc -vz dc3-qliks-ap-03.onyx.local 4747
```

Нужен ответ succeeded. Если таймаут, проверьте VPN или корпоративную сеть.

**Шаг 5. Настройки.** В блоке CONFIG файла build\_test\_dashboard.js задаются host, port, certDir, userDirectory (домен из Hub, вид ДОМЕН и логин), userId, appName, rejectUnauthorized. Правка делается в nano или другом редакторе простого текста (TextEdit портит кавычки).

**Шаг 6. Проверка синтаксиса и запуск.**

```
node --check build_dashboard_v2.js
node build_dashboard_v2.js
```

Успех: строки «Приложение создано», «Данные загружены», «Готово». Приложение появляется в Hub, раздел Work.

**Как создавать файлы в терминале.** Файл, который нельзя скачать, создаётся блоком `cat > файл << 'EOF'` ... `EOF`. Блок вставляется целиком и отдельно от других команд, строка EOF стоит на отдельной строке без лишних символов. Остальные команды выполняются по одной.

## 5. Хронология и найденные проблемы

| Проблема | Причина | Решение |
| --- | --- | --- |
| Скрипт не скачивался из чата | Карточка файла недоступна | Создание файла блоком cat с EOF |
| SyntaxError в CONFIG | Пропущена запятая, умные кавычки TextEdit | Правка в nano, проверка node --check |
| Cannot find module ...jsnpm | Две команды вставлены слитно | Команды вставлять по одной |
| Файл записался дважды, EOF слипся с командой | Блок и следующие команды вставлены вместе | Обрезка awk, затем команды запуска отдельно |
| Панель фильтров: незавершённая визуализация | У панели не объявлен список дочерних объектов | Три отдельных листбокса вместо панели |
| Графики и таблица пустые при наличии данных | Клиент Qlik добавляет к объекту около 60 служебных свойств (цвета, оси, легенда, версия), через Engine API они не появляются | Сравнение объекта из API и его копии из интерфейса, свойства по умолчанию зашиты в сборщик |

Диагностика getLayout показала, что у объектов нет ошибок и данные приходят. Значит, причина была именно в отсутствующих свойствах отображения.

## 6. Архитектура целевого приложения

Конвейер модулей. Граница безопасности проходит между модулями privacy и ai: до неё всё локально.

| № | Модуль | Назначение | Где работает |
| --- | --- | --- | --- |
| 1 | excel-reader | Чтение листов, заголовков, строк | локально |
| 2 | profiler | Типы колонок, уникальные значения, пропуски, кандидаты в ключи и связи | локально |
| 3 | privacy | Безопасный профиль по выбранному режиму, dry run, журнал отправок | локально |
| 4 | ai | Роли колонок, проект дашборда, разбор ошибок, документация | облако или локальная модель |
| 5 | spec-validator | Проверка spec.json по схеме, существование полей, разрешённые типы объектов | локально |
| 6 | qvs-generator | Скрипт загрузки по спецификации: типы, даты, календарь, связи | локально |
| 7 | delivery | Доставка Excel в Qlik | внутренняя сеть |
| 8 | builder | Создание приложения и объектов, библиотека шаблонов, раскладка | внутренняя сеть |
| 9 | verify | Диагностика объектов, сверка итогов с Excel, проверка выражений движком | внутренняя сеть |
| 10 | docs | Описание отчёта для Confluence | ИИ |

## 7. Доставка Excel в Qlik

- **Вариант А (основной): data connection на папку.** Скрипт загрузки читает lib://ИМЯ\_ПОДКЛЮЧЕНИЯ/файл.xlsx. Папка на сервере или в сетевом хранилище, у служебной учётной записи Qlik есть доступ на чтение. Подходит для обновления по расписанию.
- **Вариант Б: загрузка через QRS API** (порт 4242, те же сертификаты). Нужен, если нет доступа к папке.
- **Вариант В: inline-данные** в скрипте. Только для небольших таблиц и тестов (так сделан текущий тестовый дашборд).

## 8. Приватность

Любой облачный ИИ получает всё, что ему отправили, поэтому защита строится на том, что именно уходит наружу.

| Режим | Что уходит в ИИ | Когда использовать |
| --- | --- | --- |
| schema (по умолчанию) | Имена листов и колонок, типы, число строк и уникальных значений. Значений нет | Основной режим |
| synthetic | То же и выдуманные значения нужного типа | Когда ИИ нужны примеры форматов |
| tokenized | Имена заменены на TABLE\_A, COL\_3, значений нет. Таблица соответствия хранится только локально | Если названия колонок чувствительны |
| local | Ничего не покидает контур, используется локальная модель | Если политика запрещает внешние сервисы |

**Правила.**

- В модуль ai технически передаётся только вывод модуля privacy, а не данные из excel-reader.
- Список запрещённых колонок в конфиге (ФИО, ИНН, телефоны, контрагенты и т. п.). Они исключаются из профиля полностью. Дополнительно автоопределение по названиям и регулярным выражениям.
- Свободный текст, комментарии в ячейках и метаданные файла (автор, пути) не отправляются никогда.
- Режим dry run включён по умолчанию: пользователь видит итоговый JSON и подтверждает отправку.
- Журнал отправок (время, содержимое, адресат) хранится локально.
- Ключи API в переменных окружения. Сертификаты Qlik, ключи и журналы вне git, права chmod 600.
- Описание отчёта, которое пользователь пишет для ИИ, не содержит реальных цифр и имён клиентов.
- До первого запуска на реальных данных режимы согласуются со службой безопасности.

## 9. Роль ИИ

| Задача | Исполнитель |
| --- | --- |
| Чтение Excel, типы, пропуски, связи | код |
| Роли колонок (мера, измерение, дата, ключ), подписи, форматы | ИИ по безопасному профилю |
| Выбор показателей и срезов по описанию отчёта | ИИ |
| Формулы мер и set analysis | ИИ, затем проверка движком (CheckExpression) |
| Типы визуализаций и состав листов | ИИ из разрешённого списка |
| Раскладка по сетке 24 на 12 | код |
| Скрипт загрузки и свойства объектов | код по шаблонам |
| Разбор ошибок загрузки и пустых объектов | ИИ предлагает правку spec.json |
| Правки словами | ИИ формирует патч spec.json |
| Описание для Confluence | ИИ |

**Технически.** Единый интерфейс `provider.complete({ system, prompt, schema })`. Провайдеры подключаются отдельными файлами (Claude API, OpenAI-совместимые API, локальная модель, например через Ollama). Температура ноль, ответ строго по JSON-схеме (иначе отбрасывается и запрос повторяется), кэш по хешу входа, журнал запросов.

**Контур самоисправления.** Ошибка загрузки или объекта передаётся модели, она предлагает правку spec.json, код применяет её и пересобирает. Лимит 2-3 попытки, затем остановка и отчёт человеку.

## 10. Этапы разработки и критерии готовности

| Этап | Что делаем | Критерий готовности |
| --- | --- | --- |
| 0. Подготовка | Согласовать режимы приватности, выбрать ИИ-провайдера, подготовить обезличенный тестовый Excel, выбрать способ доставки, завести репозиторий GitLab с .gitignore | Решения зафиксированы письменно |
| 1. Ядро сборки | Перенести build\_dashboard\_v2.js в модули builder и templates, сборка из spec.json | Тестовый дашборд собирается из файла spec.json |
| 2. Чтение и профиль | excel-reader, profiler | Таблица «колонка, тип, роль» по тестовому Excel |
| 3. Приватность | privacy: режим schema, запрещённые колонки, dry run, журнал | JSON без значений, пользователь подтверждает отправку |
| 4. Генератор загрузки | qvs-generator, delivery | Загрузка без ошибок и без синтетических ключей |
| 5. ИИ-семантика и проект | Интерфейс провайдера, шаблоны запросов, схема ответа, spec-validator | spec.json по описанию проходит схему и собирается |
| 6. Проверка качества | verify: ошибки объектов, сверка сумм и числа строк с Excel, проверка выражений | Отчёт о расхождениях в консоли |
| 7. Самоисправление | Передача ошибок модели, применение патчей, лимит попыток | Типовые ошибки исправляются без пользователя |
| 8. Диалог правок и документация | Правки spec.json словами, описание для Confluence | Правка словами меняет лист |
| 9. Упаковка | README, примеры, запуск `node dashgen.js файл.xlsx`, экспорт .qvf через QRS, публикация в стрим | Запуск на новом файле без правок кода |

Этапы 0-4 дают сборку без ИИ (спецификацию пишет человек), этапы 5-7 добавляют ИИ. Работоспособность проверяется поэтапно.

## 11. Риски и меры

| Риск | Мера |
| --- | --- |
| Обновление клиента Qlik меняет свойства по умолчанию (сейчас 1.39.8) | Пересоздать шаблоны после обновления, хранить версию в конфиге |
| Даты и числа из Excel (серийные номера, десятичный разделитель) | Явные форматы в скрипте загрузки, тесты |
| Одинаковые названия колонок на разных листах дают синтетические ключи | Переименование полей, предупреждение |
| ИИ ошибается в ролях колонок и формулах | Утверждение spec.json, сверка с Excel, проверка выражений движком |
| Утечка данных | Режимы приватности, dry run, журнал, запрет значений и свободного текста |
| Большие файлы | QVD-слой, Excel как первичный источник только для небольших данных |
| Нестандартные объекты (расширения Uni) | Шаблон берётся один раз из рабочего объекта в библиотеку шаблонов |
| Ручной обмен командами и выводом | Разработка в Claude Code на Mac, где агент сам запускает команды |
